# SPEC — Linear-плагин для herdr TUI

Название: **herdr-linear-kickoff** (plugin id `rs.linear-kickoff`). Текущий прототип — bash, этот каталог.

## Зачем

Одной клавишей: выбрать задачу Linear → получить worktree на правильной ветке →
агент (claude/codex) стартует в нём, уже зная задачу целиком (описание, комментарии),
и сразу начинает работу. Без ручного «прочитай задачу LLC-964».

Не цель: полноценный Linear-клиент (создание задач с вложениями, проекты, циклы,
OAuth-приложение, интеграции с другими плагинами).

## Платформа и стек

- herdr TUI ≥ 0.9.5, macOS и Linux.
- Go + bubbletea/lipgloss, один бинарник.
- Установка: `herdr plugin install owner/repo`. `[[build]]` запускает
  `scripts/build.sh`: `go build`, а если Go нет — скачивает бинарник из GitHub
  Releases и проверяет SHA-256 (goreleaser).
- Linear GraphQL API, авторизация персональным API-ключом.

## Функции v1

### 1. API-ключ
- Нет ключа → popup сам предлагает вставить (скрытый ввод).
- Проверка запросом `viewer` → «Ключ работает: <имя>, workspace <name>».
- Хранение: macOS Keychain; Linux — Secret Service, fallback — файл `0600`
  в `HERDR_PLUGIN_CONFIG_DIR`.
- `LINEAR_API_KEY` из окружения — если задан, используется (приоритет ниже сохранённого).
- Действие «сменить ключ / выйти».

### 2. Список задач
- Режимы (вкладки): **мои** (назначенные, незакрытые) / **команда** / **бэклог**.
- Группировка по статусу, порядок — In Progress сверху; внутри — приоритет, updatedAt.
- В строке: идентификатор, статус (иконка/цвет Linear), приоритет, заголовок,
  пометка «есть worktree».
- Поиск по мере ввода (id, заголовок).
- Превью: поля задачи, описание как markdown, комментарии.
- Кэш последнего списка — popup открывается мгновенно, обновление в фоне.

### 3. Задача по номеру
- Ввод `LLC-964` или ссылки `linear.app/.../issue/LLC-964/...` → задача
  загружается, даже если её нет в текущем списке.
- `[[link_handlers]]`: клик по ссылке Linear в терминале открывает задачу в плагине.

### 4. Смена статуса
- Из списка или карточки: список workflow-состояний команды задачи.

### 5. Start (основной сценарий)
1. Перечитать задачу из Linear.
2. Определить репо: маппинг команда→репо, иначе репо текущего workspace.
3. Имя ветки по шаблону (п. 6).
4. Worktree: существующий → открыть и сфокусировать (агенту ничего не печатаем);
   иначе создать (п. 7).
5. Опционально: перевести в первый «started»-статус команды и назначить на себя,
   если задача ничья (настройка, по умолчанию вкл.).
6. В новом worktree: install-команда (если применима) → агент с промптом.
7. Переименовать workspace в `<ID>` (или по шаблону).

Порядок такой, чтобы сбой на любом шаге не оставлял полусделанного: сначала
worktree, потом изменения в Linear, потом агент. О каждом сбое — понятное сообщение.

### 6. Шаблон имени ветки
Плейсхолдеры:

| | пример |
|---|---|
| `{linear}` | `llc-964-optimize-llc-crm-for-phone` (Linear branchName) |
| `{id}` / `{ID}` | `llc-964` / `LLC-964` |
| `{team}`, `{number}` | `llc`, `964` |
| `{slug}` | `optimize-llc-crm-for-phone` (обрезается до `slug_max`) |
| `{type}` | `feat` / `fix` / `chore` … |
| `{me}` | username в Linear |

- По умолчанию `{linear}`.
- `{type}`: маппинг лейбл→тип (`Bug→fix`, `Feature→feat`, иначе `type_default`);
  опция `ask_type` — после выбора задачи короткий выбор типа с предвыбранным значением.
- Если шаблон без `{id}`/`{ID}`/`{linear}` — предупреждение: GitHub-интеграция
  Linear не привяжет PR к задаче автоматически.

### 7. Worktree
- Существующий worktree задачи ищется по: метке задачи на workspace, ветке,
  идентификатору в имени ветки — чтобы кастомный формат не плодил дубли.
- База новой ветки: `base` (по умолчанию remote default branch, `origin/HEAD`),
  с `git fetch` перед созданием; offline — локальная копия.
- Ветка уже есть на `origin` → worktree от `origin/<branch>`.
- Ветка есть локально → checkout как есть.

### 8. Агент и промпт
- Агент: `claude` / `codex` (настройка + выбор при старте опционально), команда
  запуска настраивается.
- Шаблон промпта с плейсхолдерами `{identifier} {title} {url} {description}
  {comments} {branch}`; по умолчанию — всё про задачу + «изучи задачу и предложи
  план, прежде чем писать код».
- Содержимое задачи передаётся как данные (в файле промпта, с явной пометкой
  «ниже — текст задачи»), не склеивается с инструкциями.

### 9. Install-команда
- Настраивается (`bun install` и т.п.), по репо или глобально; запускается только
  если применима (например, есть `package.json`).

### 10. Маппинг команда→репо
- `LLC → ~/code/crm`: worktree для задач команды создаётся в этом репо, плагин
  можно вызывать из любого workspace.

### 11. Метки в сайдбаре
- `herdr workspace report-metadata` с токенами `$issue`, `$issue_state`, `$issue_title`.
- Обновляются при Start/открытии и по событиям herdr; Linear опрашивается не чаще
  `label_refresh_seconds`. Отключаемо.
- В README — пример `[ui.sidebar.spaces].rows`.

### 12. Настройки
- Экран настроек в TUI + файл `config.toml` в `HERDR_PLUGIN_CONFIG_DIR`
  (правка в любом месте, одно и то же).
- Ключи: `branch_template`, `type_map`, `type_default`, `ask_type`, `slug_max`,
  `base`, `repos`, `install`, `agent`, `agent_cmd`, `prompt_template`,
  `start_sets_in_progress`, `start_assigns_me`, `labels`, `label_refresh_seconds`,
  `default_mode`.

## Действия и хоткеи

| action | что делает |
|---|---|
| `open` | popup со списком задач |
| `by-id` | сразу поле ввода номера/ссылки |
| `settings` | экран настроек |
| `logout` | удалить сохранённый ключ |

Плагины не биндят клавиши сами — README даёт готовые `[[keys.command]]`.

## Клавиши в popup (черновик)

`enter` — Start · `w` — только открыть/создать worktree · `s` — сменить статус ·
`o` — открыть в браузере · `y` — скопировать id/ссылку · `tab`/`1-3` — режимы ·
`/` — поиск · `:` — по номеру · `,` — настройки · `r` — обновить · `esc`/`q` — закрыть.

## Безопасность

- Ключ не пишется в логи, промпты и state.
- Текст задачи — недоверенные данные: не исполняется шеллом, экранируется,
  в промпте помечен как содержимое задачи.
- Сеть — только `api.linear.app` и `git fetch`.

## Открытые вопросы

- Репо на GitHub (owner).
- Перенос текущих `settings.env` → `config.toml` (миграция или просто заново).
